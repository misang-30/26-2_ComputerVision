## 1. main.cpp 흐름
### 1). 프로그램 시작점
- 진입점 : main() 함수 실행
- 모든 C++ 및 Qt 프로그램은 `main.cpp` 파일의 `int main(int argc, char *argv[])` 함수(8번 줄)에서 시작합니다.

### 2). Qt 애플리케이션 객체 생성
- `QApplication a(argc, argv);` (10번 줄)가 실행되면서 이벤트 루프 관리, GUI 스타일 설정 등 Qt 동작에 필요한 기본 환경을 초기화합니다.

### 3). 메인 창(MainFrame) 생성 및 출력

- `MainFrame w;` (11번 줄) 객체를 생성한 뒤, `w.show();` 명령으로 화면에 메인 윈도우 창을 띄웁니다. 이때 `MainFrame`의 생성자(`mainframe.cpp`) 내부 코드가 실행됩니다.

### 4).이벤트 루프 진입 (프로그램 대기/작동)

- `return a.exec();` (14번 줄)가 호출되면 Qt의 **이벤트 루프(Event Loop)**가 시작됩니다. 프로그램은 여기서 종료되지 않고 사용자의 클릭, 키보드 입력, 다른 창 생성(`imageform`, `kfc` 등) 이벤트를 처리하며 계속 대기 상태를 유지합니다.

### 5).프로그램 종료

- 사용자가 메인 창을 닫거나 종료 명령을 내리면 `a.exec()`가 값을 반환하며 `main()` 함수가 종료됩니다.

## 2. 분석

- mainframe.h 및 mainframe.cpp를 확인하면 메인 화면이 어떻게 그려지고 동작하는 지를 알 수 있다.
### 2). 서버/기타 화면 분석
- 프로젝트에 있는 `imageform.cpp`나 `kfc.cpp`는 `MainFrame` 내부의 버튼 클릭 이벤트(Signal/Slot) 등을 통해 추가로 호출되는 서브 화면/클래스일 가능성이 높습니다.

## 3. C++ 이해
### 1). 헤더 파일 Vs 소스 파일

| **구분** | **헤더 파일 (.h)**                        | **소스 파일 (.cpp)**                  |
| ------ | ------------------------------------- | --------------------------------- |
| **역할** | **선언 (Declaration)**                  | **정의 (Definition)**               |
| **비유** | 제품의 **설계도** 또는 **목차**                 | 실제 제품의 **기능 구현** 또는 **본문**        |
| **내용** | 클래스 구조, 함수 이름, 변수 타입 등 "무엇이 존재하는지" 명시 | 함수 내부의 실제 로직 코드 (`{ ... }` 안의 내용) |

### 2). main.cpp가 헤더 파일만 `#include`해도 기능할 수 있는 이유
- **컴파일러**와 링커(Linker)라는 도구가 빌드 과정에서 이 둘을 연결해주기 때문입니다.
- **전처리 (Include 단계)**
    
    - `#include "mainframe.h"`는 전처리기(Preprocessor)에 의해 `mainframe.h`에 작성된 설계도(선언) 내용을 `main.cpp` 위치에 그대로 복사해 붙여넣습니다.
        
    - 덕분에 `main.cpp`는 "아, `MainFrame`이라는 클래스가 존재하고 `show()`라는 함수를 가지고 있구나"라는 사실을 알게 됩니다.
        
- **개별 컴파일 (Compile 단계)**
    
    - 컴파일러는 `main.cpp`와 `mainframe.cpp`를 **각각 독립적으로** 컴파일하여 기계어로 된 목적 파일(`main.o`, `mainframe.o`)을 만듭니다.
        
    - `main.cpp`를 컴파일할 때는 실제 `MainFrame`의 기능 구현체가 없어도, 헤더 파일을 통해 "어딘가에 구현되어 있음"을 믿고 일단 넘어갑니다.
        
- **링킹 (Link 단계)**
    
    - 컴파일이 끝난 후 링커(Linker)가 등장합니다.
        
    - 링커는 `main.o`에서 사용된 `MainFrame`의 기능과, `mainframe.o`에 실제 작성되어 있는 구체적인 코드를 찾아 하나의 실행 파일(`.exe`)로 서로 연결(Link)해 줍니다.
